# Конструктор отчёта по проектам Bitrix24

Утилита превращает выгрузку рабочего времени из Bitrix24 в готовый markdown-отчёт,
сгруппированный по проектам с их ID.

В отличие от предыдущей версии здесь нет распознавания по картинке (OCR): ввод —
только чистый copy-paste текста, а группировка строится вокруг реестра проектов Bitrix.

## Что умеет

- разбирать вставленную выгрузку Bitrix целиком — вместе с заголовками разделов,
  служебной строкой `ID / Задача / Время`, строками `Итого:` и блоком `Итоговый результат`;
- сохранять иерархию подзадач (`→`, `→ →`) и переключать её на плоский список одной галочкой;
- хранить реестр проектов «ID проекта → название раздела» и подставлять ID в шаблон;
- привязывать нераспознанный раздел к ID проекта прямо из карточки отчёта — без повторного разбора;
- менять статусы задач и исключать их из отчёта галочкой;
- собирать отчёт по трём настраиваемым шаблонам: строки, раздела и документа;
- копировать готовый markdown в буфер обмена.

Все настройки (реестр проектов, шаблоны, режим иерархии) сохраняются в `localStorage`.

### Время не пересчитывается

Строки `Итого:` по разделам и общий `Итоговый результат` берутся из выгрузки Bitrix **как есть**
и остаются неизменными, даже если исключить часть задач из отчёта. Исключение задачи влияет
только на список строк, но не на цифры — это осознанное решение, чтобы отчёт всегда сходился
с данными в Bitrix.

## Формат ввода

Вставляйте выгрузку целиком, ничего не вычищая:

```
Внутренние задачи
ID	Задача	Время
1001	Подготовка макетов	4 ч. 10м.
Итого:	4 ч. 10м.

Проект Альфа (поддержка)
ID	Задача	Время
2001	Вёрстка функционала Карта (Frontend)	0 ч. 0м.
2002	→ Исправление багов после тестирования	5 ч. 10м.
Итого:	5 ч. 10м.

Итоговый результат
Время: 54 ч. 48м.
```

Разбор устроен как построчный конечный автомат: строка `Итого` закрывает раздел, строка
с ID и временем становится задачей, служебный заголовок таблицы пропускается, а любая
прочая строка начинает новый раздел. Строки, которые выглядят как сломанные задачи
(содержат время, но не разобрались), попадают в панель проблем, а не теряются молча.

## Архитектура: Feature-Sliced Design

```
src/
├── app/        # инициализация приложения, глобальные стили
├── pages/      # страница отчёта, компонует виджеты
├── widgets/    # самостоятельные блоки интерфейса (панели)
├── features/   # пользовательские действия (привязать проект, копировать отчёт)
├── entities/   # предметные сущности: task, project, report, settings
└── shared/     # переиспользуемое: движок шаблонов, хранилище, базовый UI, конфиг
```

Импорт разрешён только «сверху вниз»: `app → pages → widgets → features → entities → shared`.
Каждый слайс отдаёт публичное API через `index.ts`.

Ключевые модули:

| Модуль | Назначение |
| --- | --- |
| `entities/report/lib/parseBitrixText.ts` | разбор выгрузки в разделы и задачи |
| `entities/report/lib/matchSectionsToProjects.ts` | сопоставление разделов с реестром проектов |
| `entities/report/lib/buildReport.ts` | сборка итогового markdown по трём шаблонам |
| `shared/lib/template-engine/` | подстановка `{переменных}` и предупреждения |
| `entities/settings/model/settingsStore.ts` | сохраняемые настройки (Pinia + localStorage) |
| `entities/report/model/reportStore.ts` | состояние сессии: текст, разделы, результат |

Сопоставление разделов вынесено отдельно от разбора намеренно: это дешёвая чистая функция
внутри `computed`, поэтому добавление проекта в реестр мгновенно отражается на уже
разобранном тексте.

## Переменные шаблонов

- **Строка задачи:** `{id}`, `{title}`, `{duration}`, `{statusText}`, `{projectId}`, `{link}`
- **Раздел (проект):** `{projectName}`, `{projectId}`, `{list}`, `{sectionTotal}`
- **Документ:** `{date}`, `{sections}`, `{grandTotal}`
- **Ссылка:** `{id}` — ID задачи, `{projectId}` — ID группы из реестра

Если в шаблоне документа не окажется `{sections}` (или `{list}` в шаблоне раздела),
переменная допишется в конец автоматически с предупреждением — отчёт не потеряет содержимое.

### Что в шаблонах по умолчанию

Дефолтные шаблоны не печатают время — только список задач со ссылками:

```
- {statusText} №[{id}]({link}) - {title}
```

Шаблон ссылки по умолчанию подставляет ID группы прямо в URL — замените домен на свой:

```
https://bitrix.example.com/workgroups/group/{projectId}/tasks/task/view/{id}/
```

Переменные `{duration}`, `{sectionTotal}` и `{grandTotal}` никуда не делись — их можно
вернуть в шаблоны, если время в отчёте всё-таки нужно.

## Команды

```bash
npm install
npm run dev          # дев-сервер
npm run build        # проверка типов + продакшн-сборка
npm run test         # юнит-тесты (Vitest)
npm run lint         # ESLint с автоисправлением
npm run format       # Prettier
```

Стек: Vue 3 (Composition API, `<script setup>`), TypeScript, Pinia, SCSS, Vite, Vitest,
ESLint + Prettier.

## Стили

SCSS с BEM-вложенностью в scoped-блоках компонентов. Общие миксины лежат в
[core.scss](src/shared/styles/core.scss) и автоматически подключаются в каждый SCSS-блок,
поэтому импортировать их вручную не нужно.

Значения темы остаются CSS-переменными (`var(--accent)`) в
[main.scss](src/app/styles/main.scss) — это нужно, чтобы тёмная тема переключалась
в рантайме через `prefers-color-scheme`. SCSS-переменные используются только для
констант сборки: радиусы, брейкпоинты.
